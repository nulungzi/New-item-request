# 신규 자재 소요제기 처리

소요제기 품목을 넣으면 **계약(LTA / 3PP) 품목인지 Spot 품목인지** 판정하고,
계약 품목은 양식에 맞는 **구매내역서**(구매요약 + 구매세부내역)를 구글 시트로 만들어 줍니다.
핸드폰·PC 브라우저에서 모두 쓸 수 있는 Google Apps Script 웹앱입니다.

| 폴더 | 내용 |
|---|---|
| `apps-script/` | **Apps Script에 붙여넣을 파일** — `Logic.gs` (판정·계산), `Code.gs` (시트·웹앱), `Index.html` (화면), `appsscript.json` |
| `templates/구매내역서_템플릿.xlsx` | 구매내역서 서식 (구매요약 · 구매세부내역 · 구매일정 · 사업부 담당 확인) |
| `tools/` | 템플릿 생성(`build_template.py`), 미리보기 파일 생성(`apply_plan.py`) |
| `tests/` | 테스트 (`npm test`) |
| `index.html` | (이전) 구매이력 구매처·MFG 검색 페이지 |

## 판정 규칙
- 소요제기 품번이 `자재정보` 시트에 있고 **Need-by-date(출고일)가 계약시작~계약종료 안**이면 → 계약
  - Need-by-date가 없으면 작성일 기준
  - 같은 품번에 유효 계약이 여러 개면 화면에서 업체를 고릅니다 (단가 낮은 순으로 표시)
- 없으면 → Spot (`계약 없음` / `Need-by 시점 계약 만료` / `계약 시작 전` 사유 표시)
- 연도별 단가가 다르면 연도마다 줄을 나눠 적습니다. Need-by-date가 속한 기간의 단가가 쓰입니다.

## 구글 시트 준비
스프레드시트 하나에 아래 탭을 둡니다.

- **`자재정보`**: 머리글은 상위 10행 안 어디에 있어도 됩니다. 열 순서는 자유이고 이름으로 찾습니다.
  - 필수: `Item`, `계약 구분`, `업체명`, `단가`, `CUR`, `계약시작`, `계약종료`
  - 선택: `MOQ`, `UOM`, `Description`, `Material`, `Program`, `Product Name`, `Ship From`, `Lead Time`, `Shelf Life`, `Tax Code`
    (띄어쓰기·대소문자는 무시. `Ship Form`, `Leadtime` 같은 표기도 인식)
    (있으면 구매내역서에 그대로 들어갑니다)
- **`환율`**: 처음 구매내역서를 만들 때 자동으로 생깁니다. 화면에서 입력한 통화별 환율이 저장되어 다음에 다시 채워집니다.

## 설치 · 업데이트

Apps Script 편집기에는 **파일 3개**를 붙여넣습니다. 저장소 `apps-script/` 폴더의 파일과 이름·내용이 같습니다.

| 편집기 파일 | 붙여넣을 내용 |
|---|---|
| `Logic.gs` | `apps-script/Logic.gs` 전체 |
| `Code.gs` | `apps-script/Code.gs` 전체 |
| `Index.html` | `apps-script/Index.html` 전체 |

- GitHub에서 파일을 열고 오른쪽 위 **Copy raw file**(복사 아이콘) 버튼으로 복사하면 화면 글자가 섞이지 않습니다.
  붙여넣은 뒤 1번째 줄이 `// ===== 소요제기 판정 웹앱 · 파일이름` 으로 시작하는지 확인하세요.
- 붙여넣은 뒤 **저장(Ctrl+S)** 해서 파일 이름 앞 주황색 점이 사라졌는지 확인하고, **새 버전으로 배포**해야 웹앱에 반영됩니다.

### 처음 한 번
1. 자재정보가 있는 스프레드시트에서 **확장 프로그램 → Apps Script** 를 엽니다.
2. 위 표대로 `Logic.gs`, `Code.gs`, `Index.html` 을 붙여넣습니다 (스크립트 파일은 + → 스크립트로 추가).
3. **구매내역서 템플릿 올리기**: `templates/구매내역서_템플릿.xlsx` 를 구글 드라이브에 올리고
   **연결 앱 → Google Sheets로 열기** 후 **파일 → Google Sheets로 저장**합니다.
   만들어진 시트 주소의 `/d/` 와 `/edit` 사이 값이 템플릿 ID입니다.
4. 프로젝트 설정 → 스크립트 속성
   - `TEMPLATE_ID` (필수): 위 템플릿 시트 ID
   - `OUTPUT_FOLDER_ID` (권장): 구매내역서를 저장할 드라이브 폴더 ID
   - `SHEET_ID` (선택): 스크립트를 시트에 붙이지 않고 따로 만들었을 때 자재정보 시트 ID
   - `RFQ_TEMPLATE_ID` (견적요청서): `templates/견적요청서_템플릿.xlsx` 를 구글 시트로 저장한 ID
   - `RFQ2_TEMPLATE_ID` (견적요청서 양식 2 · 목록형): `templates/견적요청서_템플릿2_목록형.xlsx` 를 구글 시트로 저장한 ID
   - `SPOT_TEMPLATE_ID` (Spot 견적 구매내역서): `templates/Spot_구매내역서_템플릿.xlsx` 를 구글 시트로 저장한 ID
   - `ARCHIVE_SHEET_ID` (완료 보관): 완료한 기록을 옮겨 둘 **다른** 스프레드시트 ID (빈 스프레드시트면 됨, `완료기록` 탭은 자동 생성)
   - 자재정보 스프레드시트에 `업체정보` 탭(또는 `업체목록`): `업체명`·`이메일` 머리글 열. 한 업체를 여러 줄로 적거나 한 칸에 `;` 로 여러 주소.
     `SUPPLIER`(정식 이름)·`SITE` 열을 두면 구매내역서 Need-by 옆 SUPPLIER·SITE 칸에 들어감 (업체명으로 찾음, 대소문자·띄어쓰기 무시)
   - (선택) 편집기 왼쪽 **서비스 +** → **Gmail API** 추가: 메일 초안에 각자 Gmail 서명을 자동으로 넣음. 추가하지 않으면 Gmail 서명을 가져올 수 없으니 메일 초안 창에서 서명을 한 번 저장해 씀
5. 편집기 위쪽 함수 목록에서 **`checkSetup`** 을 고르고 ▶ 실행 → 아래 실행 로그에 ✅/❌ 로 설정 상태가 나옵니다.
6. **배포 → 새 배포 → 웹 앱**
   - **다음 사용자 인증 정보로 실행: 웹 앱에 액세스하는 사용자** (꼭 이것으로). 그래야 각 담당자가 **자기 Google 계정**으로 실행해서
     파일은 각자 드라이브에, 메일 초안은 각자 Gmail 임시보관함에 만들어집니다.
     "나"로 배포하면 모든 파일·초안이 배포한 사람 계정으로 만들어지므로, 다른 사람이 열면 로그인 화면에서 막고 배포 방법을 안내합니다.
   - **액세스 권한**: 회사 Google Workspace 계정이면 "도메인 내 사용자", 개인 Gmail 계정이면 "Google 계정이 있는 모든 사용자"
   - 담당자마다 공유가 필요합니다: 자재정보 스프레드시트 **편집**(진행기록·사용자·환율·신규 등록), 완료 보관 스프레드시트 **편집**, 템플릿 시트 3개 **보기**
   - 처음 열 때 각자 권한 승인을 한 번 합니다 ("확인되지 않은 앱" 경고가 나오면 고급 → 이동)
   업데이트 때는 **배포 관리 → 수정 → 버전: 새 버전**.

### 개발 (이 저장소)
- `Logic.gs` 는 판정·계산(순수 함수), `Code.gs` 는 시트·드라이브 입출력. Code.gs 는 Logic.gs 의 값을 함수 안에서만 씀 (파일 순서 무관)
- `npm test` 로 Logic.gs 함수와 Code.gs(가짜 시트 사용)를 검사합니다
- clasp 를 쓰면 `.clasp.json` 의 `rootDir` 을 `apps-script` 로 두고 `clasp push`

## 사용법
0. 처음 열 때 구글 계정 **권한 승인** (각자 한 번)
   - **로그인**: 담당자 이메일을 입력 → 지금 접속한 Google 계정과 같으면 로그인 (처음이면 자재정보 스프레드시트 `사용자` 탭에 자동 등록).
     다르면 "다른 Google 계정으로 접속"으로 계정을 바꿉니다. 한 브라우저에 여러 Google 계정이 로그인돼 있으면 웹앱이 잘 열리지 않을 수 있어
     담당자별 크롬 프로필(또는 시크릿 창)을 권장합니다.
   - 로그인하고 **4시간**이 지나면 자동 로그아웃 (위쪽 **로그아웃** 버튼으로 바로 로그아웃도 가능)
   - **구매내역서 만들기 / 입력용 시트 만들기**를 누르면 **폴더 선택 창**이 뜹니다. 내 드라이브 폴더를 따라 들어가
     **이 폴더에 저장** (새 폴더 만들기, 폴더 주소로 찾기 가능). 마지막에 고른 폴더에서 다시 열립니다
   - **입력용 시트 만들기**: 고른 폴더에 `소요제기 입력` 탭(Item·수량·Need-by·Program·Shelf Life·Ship·Tax)과
     `사용 방법` 탭이 있는 구글 시트를 만듭니다. 여기 적어 두고 2행부터 복사해 표에 붙여넣으면 됩니다 (머리글 같이 복사해도 됨)
1. 표에 **Item · 수량 · Need-by** 를 칸마다 입력합니다. Program · Shelf Life · Ship · Tax는 선택 (Shelf Life·Ship은 비우면 자재정보 값) (입력한 Item의 Description이 아래에 표시).
   - DB(`자재정보`)에 없는 Item이면 **신규 등록**을 눌러 그 자리에서 추가합니다.
     양식은 `자재정보` 머리글을 그대로 따르고(열을 추가하면 양식에도 생김), 계약 구분은 SPOT · LTA · 3PP.
     LTA·3PP는 업체명·단가·CUR·계약기간이 필수, SPOT은 Item만 있어도 됩니다.
   - 판정은 세 갈래: **LTA·3PP 계약** → 계약 구매내역서 / **SPOT 단가**(계약 구분 `Spot` + 단가 + Need-by가 기간 안) → Spot 구매내역서(따로) /
     **SPOT 견적**(단가 없음·DB 없음·계약 만료) → 견적요청서
   - MOQ: 숫자만 = 최소 수량, `Min 28` = 최소 28, `Multi 2` = 2개 단위. 맞지 않으면 맞는 수량을 제안합니다
   - DB 값은 사이트에서 고칠 수 없습니다 (시트에서 직접 수정). 고친 뒤 **DB 새로고침**으로 다시 불러옵니다
   엑셀에서 여러 줄·여러 칸을 복사해 아무 칸에나 붙여넣으면 그 칸부터 표가 채워집니다.
   작성일 확인 → **판정하기**
   - 계약 품목은 MOQ 미달, 작성일~Need-by 사이 리드타임 부족 같은 경고를 함께 보여줍니다
2. 계약 품목: 통화별 환율, 업체별 비고 입력 → **구매내역서 만들기** → 새 구글 시트 링크
   - 파일 이름은 자동 이름(`yymmdd 구매내역서_업체`)이 채워지고 작업자가 고칠 수 있습니다
   - 만든 뒤 화면 아래에서 **구매요약 · 구매세부내역 · 구매일정 · 사업부 담당 확인** 탭별 미리보기
     (처음 쓸 때 외부 요청 권한을 한 번 더 승인해야 합니다 — 시트를 HTML로 내보내 보여주기 위함)
3. Spot 품목
   - **DB 단가 있음**: Spot 구매내역서 대상으로 따로 모음 (양식 받은 뒤 추가)
   - **단가 없음 → 견적요청서**: 같은 자재는 Need-by가 달라도 한 줄로 합쳐 월별 칸에 수량이 나뉘어 들어감(메일 표 Need-By에는 날짜별 수량). 품목마다 Item name(필수)·Description·QPL·UOM·Remark를 적고, 제목(사업·자재특성·고정 문구·due)을 정한 뒤
     **견적요청서 만들기** → 양식 고르기 창에서 지금 품목으로 만든 예시 2개 중 하나 선택
     (양식 1 월별 수량: 같은 자재 한 줄 · 제목 `[KE] RFQ // …` / 양식 2 목록형: Need-by 마다 한 줄 · 파일 이름 `RFQ_날짜_KE_물종_이니셜_Program`,
     물종·이니셜은 다음에도 기억) → 파일을 열어 검토 → **메일 초안 만들기**에서 업체를 골라 **숨은 참조**로 Gmail **임시보관함**에 저장 (직접 보내기 전 확인)
   - 견적 회신을 받으면 **진행 중**에서 그 견적요청서를 누름 → 메일 초안에서 고른 업체가 아래에 나옴
     (메일 초안을 만들기 전에는 견적 입력 불가 — 초안에 넣은 업체만 나옴)
     ① **업체별 입력**: 업체를 누르면 화면 가운데 입력 창이 열림 → 견적요청서의 모든 품목에 업체 견적서 값(수량·MFG·UOM·U/P 또는 NO BID·
       CUR·MOQ·L/T·Shelf Life·Supplier Remarks 여러 줄) 입력, 통화 일괄·모든 품목 NO BID, **회신 없음** 체크.
       이전/다음 업체(또는 위쪽 업체 이름)로 넘기거나 닫으면 자동 저장. 외화를 고르면 그 자리에 환율 칸이 나옴(모든 업체 공통, 견적 종합 화면과 같은 값, 처음엔 DB 환율 탭 값). 업체 옆에 미입력·입력 중·입력 완료·회신 없음 표시
     ② 업체 목록 아래 **견적 종합**: 품목마다 업체 견적 비교(원화 금액·순위), 원하면 선정·검토 문구(시트에서 정해도 됨), 직전 구매·소요사업(Program) → **Spot 견적 구매내역서 만들기**
     (전체구매요약·구매내역서·견적종합·구매일정·사업부 담당 확인. 견적종합 A·B열은 시트에서 바꿔도 구매내역서가 따라감,
     전체구매요약 K열 L/I 를 바꾸면 순서가 바뀜. NO BID·회신 없음 행은 견적종합에서 회색)
   - **DB 단가 있음**(Airtech 등) 품목이 계약 품목과 같이 있으면 3단계에 **탭 2개**(계약 구매내역서 · Spot 구매내역서)가 생겨
     각각 구매일정·제목·사업부 담당자·비고를 정하고 따로 만듭니다 (Spot 구매내역서는 업체선정사유 Sole source). LTA·3PP 는 한 파일
   - 계약 구매내역서: 같은 자재·같은 계약 단가는 Need-by 가 달라도 한 줄, Need-by 칸에 `2027-05-14(500)` 처럼 날짜(수량)을 줄마다.
     T Need-by 옆 U SUPPLIER · V SITE (업체정보 탭)
   - Spot 견적 구매내역서: 구매내역서 탭 W Need-by(날짜(수량)) · X SUPPLIER · Y SITE (견적종합에서 선정한 업체), 업체 비교 칸은 Z 부터.
     견적종합 AT·AU 에 업체마다 SUPPLIER·SITE
4. 왼쪽 **진행 중**: 내가 만든 구매내역서·견적요청서만 보입니다. 소요제기가 끝나면 **완료** → 보관 파일로 옮겨 진행기록을 가볍게 유지

구매세부내역 열 배치는 예시 양식과 같고 맨 끝 T열에 `Need-by Date` 가 추가됩니다.
노란 칸(Program, 자재정보에 없는 Ship From·Leadtime, 사업부 담당자 이름)은 생성된 시트에서 담당자가 직접 입력합니다. Ship From은 Air/Ocean 드롭다운입니다.

구매내역서는 템플릿을 복사한 뒤 값만 채우므로 서식은 템플릿을 따릅니다. 서식을 바꾸려면 드라이브의 템플릿 시트를 고치면 됩니다
(단, 숨김 탭 `_proto` 의 행 순서는 그대로 두세요 — 행별 서식 원본입니다).

- 구매세부내역: 품목당 한 줄
- 구매일정: 작성일 달부터 12개월. 업무 5줄(현 재고+Open PO, PO Coverage, 품의 및 PR/PO, 업체생산 L/T, 운송·통관·검사)의

- 사업부 담당 확인: 담당자(화면에서 "이름 직급" 입력), 구매내역서 제목(= 파일 이름). 확인 날짜·날인은 담당자가 직접 (노란 칸)
